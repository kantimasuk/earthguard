# คู่มือระบบเกม EarthGuard (Single Player)

เส้นทางของ 1 รอบ: **หน้าหลัก → ตั้งค่าเกม → Pre-test → เล่นเกม → Post-test → สรุปผล → กลับหน้าหลัก / เล่นอีกครั้ง**

เอกสารนี้อธิบายว่า "ทำไมออกแบบแบบนี้" และ "โค้ดอยู่ตรงไหน" เพื่อใช้ทำความเข้าใจ อธิบายตอนนำเสนอ และต่อยอดเป็น Multiplayer

## 1. Technology Stack ที่ใช้เพิ่มในรอบนี้

**ไม่ต้องติดตั้ง package ใหม่** ทุกตัวอยู่ใน `package.json` ตั้งแต่รอบแรกแล้ว รอบนี้คือการเริ่มใช้งานจริง

| เทคโนโลยี | ใช้ทำอะไรในรอบนี้ | ไฟล์หลัก |
|---|---|---|
| **Phaser 3** | วาดโต๊ะเกมทั้งหมด (กองกลาง 3×3, กองจั่ว, คู่แข่ง, พื้นที่ของเรา) และแอนิเมชันการ์ดด้วย Tween (บิน, พลิก, สับ, ขยาย, จอสั่น) | `client/src/game/GameScene.js` |
| **Canvas 2D** (มีในเบราว์เซอร์อยู่แล้ว) | วาดหน้าการ์ด 81 ใบจากข้อมูล Excel โดยไม่ต้องมีไฟล์รูป | `client/src/game/cardArt.js` |

| **MySQL** | ตารางใหม่ `session_questions` + ใช้ตารางเดิม `game_sessions`, `test_attempts`, `test_answers`, `game_players`, `game_logs` | `database/schema.sql` |

## 2. สถาปัตยกรรม: ทำไม "เซิร์ฟเวอร์เป็นคนตัดสิน"

สเปกข้อ 8 กำหนดว่า *แยก game engine ออกจาก UI* และ *ให้ server เป็นผู้ตรวจกติกาทั้งหมด* จึงแบ่งเป็น 3 ชั้น:

```
┌────────── Client (โทรศัพท์) ──────────┐          ┌──────────────── Server (Railway) ────────────────┐
│ GameView.vue   ปุ่ม/ป๊อปอัป/ตัวจับเวลา │  Socket  │ singlePlayer.js  รับ-ส่งข้อความ ตรวจสิทธิ์ผู้ใช้     │
│ GameScene.js   Phaser วาดโต๊ะ+แอนิเมชัน │ ───────▶ │ room.js          จังหวะเกม: เวลา 20 วิ, AI, log   │
│ (ไม่มีกติกาเลย แค่ "แสดง" และ "ขอทำ")  │ ◀─────── │ engine/          ★ กติกาทั้งหมด (JavaScript ล้วน)   │
└──────────────────────────────────────┘          └───────────────────────────────────────────────────┘
```

- **Engine** (`server/src/game/engine/`) รู้แค่กติกา ไม่รู้จัก Socket.IO, MySQL, เวลา หรือหน้าจอ → เอาไปใช้กับ Multiplayer ได้ทันทีโดยไม่ต้องแก้
- **Room** (`server/src/game/room.js`) คุม "จังหวะ": นับเวลา 20 วินาที, ให้ AI คิดแล้วรอ 5 วินาที, รอ client เล่นแอนิเมชันเสร็จ, เก็บ log
- **Client** ขอทำการกระทำ เช่น `{ type: 'take', line: 'r1' }` → เซิร์ฟเวอร์ตรวจว่าถูกกติกาไหม → ส่งผลกลับ ผู้เล่นโกงด้วยการแก้โค้ดในเบราว์เซอร์ไม่ได้

> **ทำไม engine อยู่ใน `server/` ไม่ใช่ `shared/`?** ตอน deploy บน Railway ตั้ง *Root Directory = server* ทำให้มองไม่เห็นโฟลเดอร์อื่น จึงย้ายเอนจินเข้าไปใน server และให้ client ขอข้อมูลการ์ดจากเซิร์ฟเวอร์ตอนเข้าห้อง (ไฟล์ `database/tools/xlsx_to_seed.py` เขียน cards.json ให้ทั้ง 2 ที่อัตโนมัติ)

### 2.1 หลักการ "State + Events"

ทุกการกระทำคืนค่า 2 อย่าง:

1. **events** — สิ่งที่เกิดขึ้นตามลำดับ เช่น `take → endTurn → draw → draw → threat → protect → coinsStart`
2. **view** — สถานะสุดท้ายที่ "ผู้เล่นคนนี้มีสิทธิ์เห็น" (ตัดมือของ AI, เหรียญคนอื่น, การ์ดที่คนอื่นแอบดูออก)

Client เอา events มาเล่นแอนิเมชันทีละตัว (`client/src/game/reduce.js` อัปเดตภาพบนจอไปพร้อมกัน) แล้วแทนด้วย view จริงตอนจบ → **ภาพบนจอไม่มีทางคลาดเคลื่อนจากเซิร์ฟเวอร์**

### 2.2 เวลาไม่หายไปกับแอนิเมชัน

เซิร์ฟเวอร์ส่งอัปเดต → **รอ client ตอบ `sp:ready`** (เล่นแอนิเมชันเสร็จ) → ค่อยเริ่มนับ 20 วินาที / ให้ AI เล่นต่อ (ถ้า client ไม่ตอบใน 15 วินาทีจะเดินต่อเอง กันเกมค้าง)

### 2.3 ข้อความ Socket.IO ทั้งหมด

| ทิศทาง | ชื่อ | ข้อมูล |
|---|---|---|
| client → server | `sp:join` | `{ sessionId }` → ตอบ `{ ok, catalog, me, snapshot }` |
| client → server | `sp:action` | `{ type: 'take' \| 'peek' \| 'peekDecide' \| 'build' \| 'endBuild' \| 'coin', ... }` |
| client → server | `sp:ready` | `{ seq }` เล่นแอนิเมชันของอัปเดตนี้เสร็จแล้ว |
| client → server | `sp:speed` | `{ fast }` สวิตช์ "AI เล่นเร็ว" ในปุ่มตั้งค่า |
| server → client | `sp:update` | `{ seq, events, view, serverNow }` |
| server → client | `sp:intent` | AI กำลังจะทำอะไร (ไฮไลต์แถวค้างไว้ระหว่างดีเลย์) |
| server → client | `sp:timer` | เริ่มนับเวลาตัดสินใจของผู้เล่น |
| server → client | `sp:saved` | บันทึกผลเกมลงฐานข้อมูลแล้ว (เปิดปุ่มไป Post-test) |

## 3. REST API ของรอบการเล่น (`server/src/routes/sessions.js`)

ทุกเส้นต้องแนบ Firebase ID token และตรวจว่า session เป็นของผู้ใช้คนนี้เสมอ

| Method | Path | ทำอะไร |
|---|---|---|
| POST | `/api/sessions` | เริ่มรอบใหม่ `{ difficulty }` → สุ่มข้อสอบ 5 ข้อเก็บใน `session_questions` |
| GET | `/api/sessions/:id/tests/pre` | ข้อสอบก่อนเล่น (**ไม่มีเฉลย**) |
| POST | `/api/sessions/:id/tests/pre` | ส่งคำตอบ → **เซิร์ฟเวอร์ตรวจคะแนนเอง** ไม่เชื่อคะแนนจาก client |
| GET | `/api/sessions/:id/tests/post` | ข้อสอบชุดเดิม + เฉลย + คำอธิบาย (เปิดได้หลังเกมจบเท่านั้น) |
| POST | `/api/sessions/:id/tests/post` | ส่งคำตอบ → session เปลี่ยนเป็น `completed` |
| GET | `/api/sessions/:id/summary` | อันดับ, ตารางคะแนน, Pre/Post, Game Log ทั้งหมด |
| DELETE | `/api/sessions/:id` | **ออกจากเกม** → ลบรอบนี้ (ผลเกม + Pre + Post ถูกลบตามด้วย `ON DELETE CASCADE`) |

## 4. แต่ละหน้า

### 4.1 ตั้งค่าเกม — `client/src/views/GameSetupView.vue`
การ์ด 3 ระดับ (ง่าย/ปานกลาง/ยาก = AI 2/3/4 ตัว พร้อมรูป AI ที่จะเจอ) + ปุ่ม "กติกาย่อ" (Pop-up) → กดเริ่ม = สร้าง session → Pre-test

### 4.2 Pre-test / Post-test — `client/src/views/TestView.vue` (ไฟล์เดียวใช้ 2 แบบ)
- หน้าแนะนำก่อนเริ่ม (เวลายังไม่เดินจนกว่าจะกด "เริ่ม")
- ทีละข้อ มีแถบความคืบหน้า 5 ช่อง + เวลา 2:00 (เหลือ 20 วิ เปลี่ยนเป็นสีแดง)
- **Pre**: ไม่เฉลย ตอบแล้วเลื่อนไปข้อถัดไปทันที · หมดเวลา → ข้อที่ไม่ตอบนับผิด เข้าเกมทันที
- **Post**: ตอบแล้วขึ้นเขียว/แดง + เครื่องหมายถูก/ผิดเด้ง + คำอธิบาย
- ปุ่มฟันเฟือง (`GameSettings.vue`) มุมขวาบน: เพิ่ม/ลด/ปิดเสียง + ออกจากเกม

### 4.3 เล่นเกม — `client/src/views/GameView.vue` + `client/src/game/`

โครงหน้าจอแนวนอน (ปรับขนาดอัตโนมัติตั้งแต่ iPhone SE ถึงคอมพิวเตอร์):

```

│  คู่แข่ง (AI)   │   ▼   ▼   ▼            │ กองจั่ว    │  คุณ   ●● เหรียญ   มือ 5    │
│  ใบเตย 3 ใบ    │ ▶ [การ์ด][การ์ด][การ์ด] │            │  สิทธิในมือ [ ][ ]          │
│  [สิทธิที่สร้าง] │ ▶ [การ์ด][การ์ด][การ์ด] │ สาธารณะ   │  การ์ดกิจกรรม ตาราง 3×3    │
```

**ออกแบบให้ใช้ง่ายบนโทรศัพท์**
- การ์ดกิจกรรมในมือแสดงเป็น **ตาราง 3×3 (สัญลักษณ์ × หมายเลข)** แทนการเรียงการ์ดเล็ก ๆ → เห็นทันทีว่าสร้างสิทธิได้หรือยัง
  (เชิงเนื้อหา = มีครบ 3 คอลัมน์, เชิงกระบวนการ = แถวสัญลักษณ์มี 3 ใบ)
- ของที่เล็กเกินไปกลายเป็น **Pop-up**: แตะการ์ด = รายละเอียด+ความรู้, แตะพื้นที่ของเรา = การ์ดทั้งหมด (บอกว่ายังขาดอะไร), แตะคู่แข่ง = สิทธิที่เขาสร้าง, แตะโซนสาธารณะ, ความสามารถ, Game Log, กติกาย่อ
- ปุ่มลูกศรข้างแถว/คอลัมน์ **แตะครั้งเดียวหยิบทั้งแถว** (ตามสเปก) และแสดงเฉพาะตอนเป็นตาเรา
- ระหว่างมีป๊อปอัปเปิด กระดานจะไม่รับการแตะ (กันแตะทะลุ)

**ข้อความภาษาไทยบนการ์ด**: ตัดคำด้วย `Intl.Segmenter('th')` จึงไม่ขึ้นบรรทัดใหม่กลางคำ และโหลดฟอนต์ Kodchasan ให้เสร็จก่อนวาด (`boot.js`)

## 5. Game Engine — กติกาในโค้ด (`server/src/game/engine/`)

| ไฟล์ | หน้าที่ |
|---|---|
| `catalog.js` | แปลง cards.json → รหัสที่ใช้ง่าย (`AIR WAT FOD CLM ECO TOX` เชิงเนื้อหา, `INF PAR JUS` เชิงกระบวนการ, สัญลักษณ์ `INF/PAR/JUS`, หมายเลข 1–3) |
| `rng.js` | ตัวสุ่มแบบกำหนด seed ได้ → เล่นซ้ำ/ทดสอบได้ |
| `analysis.js` | วิเคราะห์มือด้วยตาราง 3×3, หาทางทิ้งการ์ดที่ดีที่สุด, ตรวจการ์ดที่ผู้เล่นเลือกทิ้ง |
| `engine.js` | **กติกาทั้งหมด**: จัดกอง 3 ช่วง, หยิบแถว, สร้างสิทธิ, เติมกองกลาง/เปลี่ยนช่วง, ภัยคุกคาม 4 ขั้น, ความสามารถ 3 แบบ, จบเกม, คะแนน, มุมมองแยกผู้เล่น |
| `ai.js` | AI 3 แบบ: `SmartAI` (ใช้จริง), `SimpleAI` และ `RandomAI` (ไว้วัดผลและทดสอบ) |
| `describe.js` | แปลง event เป็นข้อความไทยสำหรับ Game Log |

**สถานะเกม (stage)**: `take` → (`peek`) → `build` → เติมกองกลาง → (ภัยคุกคาม → `coins`) → ตาถัดไป … → `ended`

**กรณีที่สเปกไม่ได้เขียนไว้ และเลือกไว้ดังนี้** (แก้ได้ใน `engine.js`)
- ผู้เล่นมีสิทธิที่ป้องกันภัยเดียวกันหลายใบ → นับ +1 ให้ **ใบที่ใกล้ได้โบนัสที่สุด** (ดีต่อผู้เล่นที่สุด)
- สิทธิเชิงกระบวนการป้องกันภัย SLAPP ได้ (ตามข้อมูลการ์ด) แต่ไม่มีตัวนับ/โบนัส (โบนัสเป็นของสิทธิเชิงเนื้อหาเท่านั้น)
- ถ้าสร้างสิทธิครบทุกใบที่สร้างได้แล้ว ระบบจบตาให้อัตโนมัติ
- การ์ดใบบนสุดที่ดูได้ = ใบที่จะถูกเปิดลงกองกลางตอนจบตาของเรา

## 6. AI ฉลาดขึ้นอย่างไร (`ai.js`)

ใช้ลำดับความสำคัญตามสเปก 5.7 แต่แต่ละข้อ "คิด" มากกว่าทำตามตรง ๆ และ **ใช้เฉพาะข้อมูลที่ผู้เล่นจริงรู้ได้** (ไม่แอบดูกองจั่วหรือมือคนอื่น)

1. **สร้างสิทธิทันทีที่ทำได้** แต่ค้นหาชุดที่ได้ค่ารวมสูงสุด เช่น มี 2 สิทธิที่ใช้การ์ดชนกัน จะเลือกทิ้งแบบที่สร้างได้ทั้งคู่
2. **หยิบแถว**: จำลองทุกแถว (หรือทุกชุด 84 แบบเมื่อปลดล็อก "มีส่วนร่วม") แล้วให้คะแนนมือหลังหยิบ
   - ค่าสิทธิที่สร้างได้ทันที + ศักยภาพที่ขาดอีก 1–3 ใบ
   - **นับการ์ด**: ภัยคุกคามใบไหนยังไม่ออก → สิทธิที่ป้องกันภัยที่เหลือได้มีค่ามากขึ้น
   - ช่วงท้ายเกม (ช่วง 3) ให้ค่ากับ "สร้างได้เลย" มากกว่า "สะสมไว้" เพราะเกมอาจจบทุกเมื่อ
   - มือใหญ่ในช่วงที่มีภัยคุกคาม = เสี่ยงเสียการ์ด → หักคะแนนเล็กน้อย
3. **เหรียญ**: ใช้ทุกครั้งที่ไม่ปลอดภัย เพราะคำนวณแล้ว "ไม่มีข้อเสีย" (สำเร็จ = ไม่เสียการ์ดและเหรียญหาย ไม่ถูกหักคะแนนตอนจบ, ไม่สำเร็จ = ได้เหรียญคืน)
4. **ดูการ์ดบนสุด**: เจอภัยคุกคามที่ตัวเองป้องกันได้ → ปล่อยไว้ให้คนอื่นเจอ, ป้องกันไม่ได้ → ซ่อนไว้ใต้กอง, เจอการ์ดจบเกม → ปล่อยไว้ถ้าตัวเองนำ, เจอการ์ดสิทธิ → ซ่อนไม่ให้คนถัดไปได้

**ผลวัดจริง** (`npm run simulate`, จำลอง 500 เกม):

| การแข่ง | Smart AI ชนะ | ถ้าเก่งเท่ากันควรชนะ |
|---|---|---|
| Smart vs Simple (3 คน) | ≈ 88% | 33% |
| Smart vs Simple (4 คน) | ≈ 78% | 25% |
| Smart vs Simple (5 คน) | ≈ 86% | 20% |
| Smart vs Random (3 คน) | ≈ 83% | 33% |

(ตัวเลขนี้ใช้ในสไลด์นำเสนอได้ — แสดงว่า AI ตัดสินใจได้ดีกว่าการทำตามกฎตรง ๆ อย่างชัดเจน และลำดับที่นั่งไม่ได้เปรียบกัน ≈ 20% ต่อที่นั่งเมื่อ 5 คนเก่งเท่ากัน)

## 7. ออกจากเกม / เชื่อมต่อหลุด

- ⚙ → ออกจากเกม → ยืนยัน → `DELETE /api/sessions/:id` → **ไม่บันทึกอะไรของรอบนี้เลย** (ผลเกม, Pre, Post) แล้วปิดห้องบนเซิร์ฟเวอร์ · เกมไม่หยุดระหว่างเปิดป๊อปอัป ตัวจับเวลายังเดิน
- เน็ตหลุดระหว่างเกม: ห้องยังอยู่บนเซิร์ฟเวอร์ 3 นาที ต่อกลับได้แล้วเห็นสถานะล่าสุด (ระหว่างนั้นถ้าถึงตาเรา ระบบเล่นแทนเมื่อหมดเวลา)
- ค่าเสียงเก็บใน localStorage → คงอยู่ข้ามหน้าและข้ามรอบ
- ปิดเบราว์เซอร์กลางคัน: session ค้างสถานะ `in_progress` ในฐานข้อมูล (ไม่นับเป็นผลที่สมบูรณ์ เพราะ `completed` เฉพาะรอบที่ทำ Post-test แล้ว)

## 11. ใส่รูปการ์ดของทีมเอง

1. วางไฟล์รูปไว้ที่ `client/src/assets/cards/`
2. ตั้งชื่อไฟล์ตาม **รหัสแบบการ์ด** เช่น `R-AIR-A.webp`, `A-INF-1-A.webp`, `T-HEAT.webp`, `E-TIP.webp` และหลังการ์ด `back.webp` — รายชื่อครบ 42 แบบอยู่ใน `client/src/assets/cards/README.md`
3. รีเฟรชหน้าเว็บ (หรือรัน `npm run dev` ใหม่)

การ์ดใบไหนมีรูป → ใช้รูป, ไม่มี → ใช้การ์ดที่วาดด้วยโค้ด (ทยอยใส่ได้) · ระบบตัดรูปให้เป็นสัดส่วนการ์ด 5:7 และทำมุมโค้งให้เอง · แนะนำ 500×700 px ไฟล์ .webp ละไม่เกิน ~80 KB

โค้ดที่เกี่ยวข้อง: `client/src/game/cardImages.js` (หาไฟล์ด้วย `import.meta.glob` ของ Vite → เพิ่ม/ลบรูปไม่ต้องแก้โค้ด), `cardArt.js` (`drawImageCard`), `services/preload.js` (โหลดรูปการ์ดล่วงหน้าตอนหน้า Loading)
